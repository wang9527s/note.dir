# watchOS 蓝牙后台机制

## 1. 系统层限制

watchOS 第三方 app 不支持 `bluetooth-central` 后台模式（这是与 iOS 最大的差异）。app 退到后台后系统只给很短的运行窗口，随后 suspend（冻结进程）。suspend 后系统在收到 BLE notify 时可能短暂唤醒 app，但有配额限制。

### 唤醒配额

> - 单次前台会话内后台唤醒约 ** x 次**，app 切到前台后重置
> - 24 小时内只能唤醒 ** y 次**，重启 AW 或卸载重装 app 可恢复

## 2. 保活唤醒


### 策略

```
0 = unknown    未确定
1 = active     AW app 在前台
3 = background AW app 在后台短暂运行
4 = suspend    AW app 已被系统冻结
```


**active / background** —— **AW 主动上报**：AW 端监听的 app window hidden 状态，判断是active还是background。通过信令交互通知手机(对端)
PS: active/inactive/background 都需要监听

综合考虑功耗和性能，手机会有短暂的心跳；在background后，手机会推测aw进入suspend。

### 场景 - 拉活

对端是suspend，本端发送gatt notity消息，进行拉活动。
